# S5 — Replay Tuning

**Status:** implemented; local acceptance verified. Reference-host benchmarks and hosted CI remain
pending.

## Outcome and scope

Settle eligible short waits in the live isolate, without changing canonical HTTP admission or durable
fallback. The backend owns an inclusive 1,000 ms per-wait threshold and a shared 1,000 ms cumulative
allowance per replay. The allowance covers SDK `replay.sleep` and the full `httpCall` admission flow,
including matched redirect hops and short `429` delays. Longer waits and waits without remaining
allowance defer. Reserve allowance before sleeping; refund unused time on cancellation using a
monotonic clock.

The existing synchronous inline batch accepts `host` and `sleep` members. It freezes JavaScript
fibers and timers while the isolate parks its CPU lease. A sleep result is raw `null`; host members
retain typed success or failure results. The 30-second script limit, 30-second settlement limit,
five-minute absolute limit, and eight-second HTTP-attempt limit still apply.

The host gate stores completed members and HTTP continuation in backend-only `pendingInline` queue
metadata, not script input or echo. It validates request identities and encoded-byte bounds. The
parent validates the pending trace, reuses completed request slots, and resumes retained redirect,
hop, attempt, and block progress. Normal handoff retains the ticket; interrupt cleanup uses the last
declaration binding. Retained evidence is charged at three times its encoded size. Evidence preflight
may defer before dispatch when maximum result and continuation evidence cannot fit, such as multiple
maximum-sized HTTP results. Short waits do not bypass resource admission.

HTTP keeps Redis global lane, tenant, and plugin fairness; claim-before-network; live policy
re-resolution; fail-closed admission errors; egress checks; and redirect semantics. Live settlement
shares control flow with durable activities and does not start child workflows.
