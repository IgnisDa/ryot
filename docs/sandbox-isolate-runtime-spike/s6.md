# S6 — Linux Syscall Allowlist

**Status:** syscall-policy scope implemented; required checks, both Linux native/launcher suites,
and the confined backend/SDK suites verified.

## Contract

The Linux x86_64 and aarch64 sidecars use a default-deny seccomp allowlist installed after snapshot
verification and before V8 or worker startup. Unknown or unlisted syscalls and rejected arguments
return `EPERM`; `clone3` returns `ENOSYS` for glibc's pthread path. Architecture validation and x86_64
x32 rejection remain. Only the exact observed pthread `clone` flags are allowed, so process creation,
namespace creation, and alternate sharing or exit-signal flags are rejected.

The complete syscall set, argument restrictions, and runtime rationale are in
[`kernel/sandboxd/README.md`](../../kernel/sandboxd/README.md#linux-syscall-policy). Landlock still denies
read-only opens with `EACCES`, and the sidecar still verifies that outcome after lockdown. Filesystem,
network, execution, cross-process inspection, dump protection, empty environment, descriptor hygiene,
fixed trusted paths, and backend/sidecar UID separation remain enforced. Installation failure exits
with 71.

The pinned Rust, Deno, and prebuilt V8 dependencies, counting allocator, `--no-turbofan`, version
constants, resource limits, scheduling, and S5's shared short-wait budget remain. This slice claims
only tighter OS confinement: newly encountered syscalls need explicit justification before they can
run. It claims no memory or latency improvement. Custom V8 builds, its memory-corruption sandbox,
pointer compression, and allocator replacement remain separate deferred work. A syscall allowlist
does not eliminate V8 exploits or guarantee cross-user isolation within a shared address space.

## Evidence and acceptance

Controlled `strace -ff -tt` runs of the admission, execution, limits, protocol, and surface suites
passed on native x86_64 Linux `7.0.0-38-generic` and on aarch64 Linux `6.8.0-117-generic` under Docker's
default filter. Each trace separates successful seccomp installation from post-lockdown calls and
follows newly created threads. Both architectures use the same pthread flags. Optional VMA naming
and executable-path lookups seen in traces are denied rather than added to the policy.

| Acceptance | Named coverage |
| --- | --- |
| Unknown/unlisted calls, dangerous operations, process/namespace creation, x32, clone3 errno, and inherited thread confinement | `confinement_denies_files_sockets_and_dangerous_syscalls` |
| Self-directed crash signals and disabled core dumps | `confined_abort_delivers_its_signal_without_a_core_dump` |
| Confined execution and empty environment | `the_sidecar_serves_while_confined_with_an_empty_environment` |
| Landlock and seccomp installation failures stop startup | `startup_fails_when_confinement_cannot_be_applied` |
| Post-lockdown Landlock self-check fails closed when enforcement is bypassed | `landlock_is_verified_inside_the_running_sidecar` |
| Core/data/full workloads, plugin imports, host calls, asynchronous waits, and inline cancellation | `execution.rs`, including `each_tier_runs_its_fixture_module`, `host_calls_are_answered_by_the_stub_host`, and `synchronous_inline_settlement_freezes_timers_and_wakes_on_cancel` |
| Both lanes, CPU/memory admission, priorities, and recycling | `admission.rs`, including `background_lane_threads_run_at_lower_priority` and both `the_sidecar_drains_and_restarts_*` tests |
| CPU/heap/external-memory/deadline termination and crash handling | `limits.rs`, including `loops_and_fill_loops_are_stopped_at_the_cpu_limit`, `array_buffers_and_external_memory_are_contained`, and `crash_probes_do_not_crash_the_process` |

| Launcher trust × snapshot keys, identities, descriptor hygiene, and termination attestation | the `sandboxd.yml` launcher steps, including `sidecar_identity_environment_and_descriptors_are_confined` |
| S5 live/replayed waits, cancellation, backstop, and disposal through the backend | Confined backend suite, SDK workflow tests, `runner-integration.test.ts`, and `native-memory-disposal.test.ts` |
