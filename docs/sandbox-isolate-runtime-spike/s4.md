# S4 — Image and deployment

**Status:** implemented for the reviewed deployment-only scope. Local checks and tests are waived;
the native image CI jobs and live platform deployments have not been run for these changes.

## Contract

- Keep one image containing the backend and its sidecars; no delegated cgroup subtree or separate
  sidecar cgroups are required.
- Do not define deployment CPU, memory, or PID ceilings or fixed resource sizing. Keep the
  runtime's existing per-isolate limits, aggregate admission, and visible-memory discovery.
- Keep native Linux amd64 and arm64 release builds. Both architectures build the release image
  and run the existing six-key sandbox smoke under Docker's default security settings.
- The Compose example sets no resource ceilings. Helm retains its scheduling requests without
  adding resource limits. Fly leaves Machine resource selection to the operator.
- Document Linux Landlock/seccomp support, the fixed backend and sidecar identities, the setuid
  launcher, writable runtime paths, and the incompatibility with `no-new-privileges`, `nosuid`,
  and Kubernetes Restricted pod-security policy.
- Reject Helm security settings that select the wrong backend UID/GID, disable the setuid
  launcher, or make its runtime and application paths read-only.
- Keep `SERVER_LANES=all` as the default. Explain split mode's extra processes and memory
  requirements without claiming S3's unproven E2 latency acceptance.

## Image verification

`.github/workflows/main.yml` publishes native `linux/amd64` and `linux/arm64` images by digest
and joins them into multi-arch manifest lists. `.github/workflows/sandboxd.yml` builds and runs
the release image on native `ubuntu-24.04` and `ubuntu-24.04-arm` runners.

The runtime check reuses `dist/prepare-sandbox-runtime.js`, already shipped by the image, with
network access disabled and no explicit resource ceilings. It executes
`system/core`, `system/data`, `system/full`, `user/core`, `user/data`, and `user/full`, checks
runtime alias identity and host-call results, and verifies sidecar UID/GID 1002, seccomp,
`no_new_privs`, and `oom_score_adj`. Snapshot digest verification is part of sidecar startup.
