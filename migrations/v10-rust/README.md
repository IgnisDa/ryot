# Legacy Bootstrap

This shipped startup migration converts deployed V1 Rust data to the V2 TypeScript schema. Fresh V2 installs and normal E2E do not exercise it.

## Model And Restart Behavior

User-authored data migrates fully. Provider data migrates only when user data references it because V2 population can reconstruct the rest.

| V1 data                        | V2 rule                                                                                                                     |
| ------------------------------ | --------------------------------------------------------------------------------------------------------------------------- |
| User-authored entities         | Preserve IDs and properties; no provider.                                                                                   |
| Referenced provider entities   | Preserve identity and name as global skeletons with empty properties and `populated_at = NULL`.                             |
| Unreferenced provider entities | Omit.                                                                                                                       |
| Provider identity              | `(external_id, entity_schema_slug, provider_id)`, plus `user_id` for user scope. Provider ID, not script ID, is provenance. |
| Relationships                  | Preserve user-authored rows; population rebuilds provider-derived rows.                                                     |

`_referenced_global_entity_ids` includes references from seen rows, reviews, collections, library membership, and user-authored relationship endpoints.

Legacy tables are renamed before Drizzle creates V2 tables; copying starts afterward. The migration resolves definitions, providers, integration providers, and current scripts from the active `media` and `fitness` packages by stable plugin ID plus local slug. Missing, stale, ambiguous, unsupported, or invalid required mappings abort startup.

Users are inserted first. Deterministic IDs, exact installation identities, conflict guards, and persistent claims make completed work safe to encounter after restart; claims created by an earlier attempt are not replaced. Normal bootstrap then creates built-in views and default notification subscriptions with plugin user-bootstrap dispatch disabled. Only documented omissions and restart guards may skip data; all other unexpected state fails the migration.

## Mappings And Omissions

| Domain                    | Mapping                                                                                                                                                                                                                                                                                                                                                          | Intentional omissions or constraints                                                                                                                                                                                                                                                                |
| ------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Users/auth                | Preserve IDs; use lowercase email usernames or `<normalized-name>@ryot.local`, resolving collisions with `+<id>`; mark email verified. Disabled users map to `disabled_at`; OIDC users get minimal Better Auth account stubs.                                                                                                                                    | Password credentials use god-mode reset links. Omit sessions, 2FA, OAuth redirect URL, admin lot, and token lifetime.                                                                                                                                                                               |
| Media/provider entities   | Migrate referenced metadata, groups, people, and companies as skeletons; custom rows in full. Expand show/podcast seasons and episodes into child entities and relationships.                                                                                                                                                                                    | Omit unreferenced provider rows, provider-only suggestions/genres/relationships, and V1 translations.                                                                                                                                                                                               |
| Measurements              | Create `measurement` entities with deterministic MD5 IDs from user and timestamp; normalize statistic keys.                                                                                                                                                                                                                                                      | Omit assets and per-statistic units.                                                                                                                                                                                                                                                                |
| Fitness                   | Map workouts/templates to entities, sets to events, and template/repetition links to relationships; normalize media to top-level `images`/`videos`. GitHub exercises are populated catalog entities; custom exercises migrate fully.                                                                                                                             | GitHub rows cannot have creator IDs. No post-import revision scheduler exists in V2.                                                                                                                                                                                                                |
| Seen lifecycle            | Resolve show/podcast positions to episodes; regular child events use the parent session, specials are sessionless; completed episodes get explicit `complete` events. Replay by `occurredAt`, `createdAt`, then ID. Later progress reopens an episode. Parent `dropped` and `on_hold` events use self-session and interrupt child progress.                      | Skip and report unresolved positions. Anime/manga remain flat. Empty/special-only series cannot complete. Parent completion/rewatch requires complete regular coverage and production status `Ended`, `Canceled`, or `Cancelled`; otherwise status is `caught_up`.                                  |
| Reviews                   | Map to historical `review` events outside lifecycle sessions, with episode resolution.                                                                                                                                                                                                                                                                           | Omit visibility and comments.                                                                                                                                                                                                                                                                       |
| Collections/library       | Map global `user_to_entity` to `in-library`; map normal collections and historical add events. `Owned` annotates library relationships; `Monitoring` creates `media-monitoring` for monitorable global provider entities.                                                                                                                                        | Skip collections and user-owned custom exercises in the `user_to_entity` path.                                                                                                                                                                                                                      |
| Assets                    | Stream legacy S3 locators, hash bytes, copy per user to `permanent/<owner-namespace>_<sha256>.<extension>`, register managed assets, then rewrite properties. Delete old objects only after commit and only when all references migrated.                                                                                                                        | Unowned, unresolved, or unsupported locators are reported and retained. Post-commit deletion failures warn but do not invalidate migrated data.                                                                                                                                                     |
| Integrations              | Resolve providers from the exact media package, validate current settings, and attach the owner's installation. Migrate unexpired debounce and YouTube Music cache rows as persistent Redis claims with remaining expiry.                                                                                                                                        | Report and skip removed `generic_json`; other unknown providers/settings fail. Omit trigger history. Ambiguous or unresolved cache targets are reported and skipped. Set `RYOT_PLUGIN_MEDIA_PROGRESS_UPDATE_THRESHOLD_HOURS` separately if the old non-default threshold must survive claim expiry. |
| Notifications/preferences | Convert supported notification specifics; map `display_nsfw` to `allowNsfw` with V1's `true` default, `disableIntegrations`, and feature flags to built-in saved-view disabled state using exact installation IDs. Media flags control lot, people/company, and group views; fitness flags control fitness views; the collections flag controls the kernel view. | Drop credential-bearing descriptions and event filters. Provider languages start as global `null`; Audible marketplace is provider identity and is not migrated as a preference. Feature flags affect view disablement only.                                                                        |

Plugin-owned definitions and views retain qualified stable plugin provenance; kernel definitions retain `NULL` provenance. No private package or unsupported plugin state is synthesized. Mapping files remain authoritative for exact field transforms, clamping, deterministic IDs, and SQL.

When legacy debounce rows collapse to one V2 fingerprint, preserve the longest remaining expiry. Normalize known provider labels and resolve show/podcast markers to episode IDs; ambiguous browser-extension, removed-provider, and unresolved targets are reported omissions. A pending YouTube Music row creates `seen`; a completed row creates both `seen` and `completed`.

## Reports And Failures

After Drizzle creates V2 schema, each phase appends structured rows to `migration_report`: sequence, timestamp, phase, level, message, optional count, and elapsed seconds. The table remains for inspection; pre-schema table renames cannot report there.

Allowed warnings are limited to unresolved seen/review episodes, unresolved legacy S3 assets, and post-migration S3 deletion failures. Any other warning or unexpected state aborts startup. On restart, existing report rows remain and orchestration logs only newly appended rows.

## Validation Runbook

Restore a legacy dump, run migration-only mode, then inspect logs, `migration_report`, and migrated rows in the same database:

```bash
just restore-db 'tmp/file.sql'
cd 'apps/server' && bun run run-migration
```

The god-mode Migration Report shows warnings first, then newest rows. Validate both normal and larger available dumps; generated-SQL tests do not exercise startup orchestration, external assets, or realistic volume.
