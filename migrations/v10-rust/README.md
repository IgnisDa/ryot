# Legacy Bootstrap

This shipped startup migration converts deployed V1 Rust data to the V2 TypeScript schema. Fresh V2 installs and normal E2E do not exercise it.

## Model And Restart Behavior

User-authored data migrates fully. Provider data migrates only when user data references it because V2 population can reconstruct the rest.

| V1 data                        | V2 rule                                                                                                                     |
| ------------------------------ | --------------------------------------------------------------------------------------------------------------------------- |
| User-authored entities         | Preserve IDs and properties; no provider.                                                                                   |
| Referenced provider entities   | Preserve identity and name as global skeletons with empty properties and `populated_at = NULL`.                             |
| Unreferenced provider entities | Omit.                                                                                                                       |
| Provider identity              | `(external_id, entity_schema_slug, provider_id)`, plus `user_id` for user scope. Provider ID, not script ID, is provenance. |
| Relationships                  | Preserve user-authored rows; population rebuilds provider-derived rows.                                                     |

`_referenced_global_entity_ids` includes references from seen rows, reviews, collections, library membership, and user-authored relationship endpoints.

Legacy tables are renamed before Drizzle creates V2 tables; copying starts afterward. The migration resolves definitions, providers, integration providers, and current scripts from the active `media` and `fitness` packages by stable plugin ID plus local slug. Missing, stale, ambiguous, unsupported, or invalid required mappings abort startup.

Users are inserted first. Deterministic IDs, exact installation identities, conflict guards, and persistent claims make completed work safe to encounter after restart; claims created by an earlier attempt are not replaced. Normal bootstrap then creates built-in views and default notification subscriptions with plugin user-bootstrap dispatch disabled. Only documented omissions and restart guards may skip data; all other unexpected state fails the migration.

| Domain                    | Mapping                                                                                                                                                                                                                                                                                                                                                          | Intentional omissions or constraints                                                                                                                                                                                                                                                                                                      |
| ------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Users/auth                | Preserve IDs; use lowercase email usernames or `<normalized-name>@ryot.local`, resolving collisions with `+<id>`; mark email verified. Disabled users map to `disabled_at`; OIDC users get minimal Better Auth account stubs.                                                                                                                                    | Password credentials use god-mode reset links. Omit sessions, 2FA, OAuth redirect URL, admin lot, and token lifetime.                                                                                                                                                                                                                     |
| Media/provider entities   | Migrate referenced metadata, groups, people, and companies as skeletons; custom rows in full. | Collections/library       | Map media `user_to_entity` rows, global and custom, to `in-library`; map normal collections and historical add events. `Owned` annotates library relationships; `Monitoring` creates `media-monitoring` for monitorable global provider entities.                                                                                                                | Skip collections and exercises in the `user_to_entity` path; no fitness schema reads `in-library`.                                                                                                                                                                                                                                        |
| Assets                    | Stream legacy S3 locators, hash bytes, copy per user to `permanent/<owner-namespace>_<sha256>.<extension>`, register managed assets, then rewrite properties. | Integrations              | Resolve providers from the exact media package, validate current settings, and attach the owner's installation. Provider languages start as global `null`; Audible marketplace is provider identity and is not migrated as a preference. Feature flags affect view disablement only. Drop `disable_watch_providers` and the per-lot preferred watch-provider lists; both were V1 display filters. |

Plugin-owned definitions and views retain qualified stable plugin provenance; kernel definitions retain `NULL` provenance. No private package or unsupported plugin state is synthesized. Mapping files remain authoritative for exact field transforms, clamping, deterministic IDs, and SQL.

When legacy debounce rows collapse to one V2 fingerprint, preserve the longest remaining expiry. Normalize known provider labels and resolve show/podcast markers to episode IDs; ambiguous browser-extension, removed-provider, and unresolved targets are reported omissions. A pending YouTube Music row creates `seen`; a completed row creates both `seen` and `completed`.

## Reports And Failures

After Drizzle creates V2 schema, each phase appends structured rows to `migration_report`: sequence, timestamp, phase, level, message, optional count, elapsed seconds, and — on anomalies only — a stable `code`. The table remains for inspection; pre-schema table renames cannot report there.

A warning also writes one row per offending record to `migration_report_detail`, keyed to its summary by `report_seq`. Legacy `seen`, `review` and `application_cache` are dropped when the migration finishes, so each detail row denormalises everything needed to explain that record — the title, the position asked for, and what the cached metadata actually held. Emission is uncapped; the god-mode API serves the first 100 details per summary alongside the true total, and the rest stay queryable in SQL. Only a sample reaches the terminal log.

Warnings are allowed by `code`, never by message text, so report copy can be rewritten without changing abort behaviour:

| Code                                  | Phase                                                        | Meaning                                                                                    | Per-record detail |
| ------------------------------------- | ------------------------------------------------------------ | ------------------------------------------------------------------------------------------ | ----------------- |
| `seen-episode-absent`                 | `seen -> event`                                              | The watched position is not in the parent's stored episode list.                           | yes               |
| `seen-episode-ambiguous`              | `seen -> event`                                              | Several stored episodes claim the watched position.                                        | yes               |
| `seen-episode-malformed`              | `seen -> event`                                              | The legacy row stored no usable episode number.                                            | yes               |
| `review-episode-absent`               | `review -> event`                                            | The reviewed position is not in the parent's stored episode list.                          | yes               |
| `review-episode-ambiguous`            | `review -> event`                                            | Several stored episodes claim the reviewed position.                                       | yes               |
| `integration-cache-provider-unmapped` | `application_cache -> integration progress persistent cache` | The service that produced a debounce marker has no V2 equivalent.                          | yes               |
| `integration-cache-entity-unresolved` | `application_cache -> integration progress persistent cache` | A debounce marker points at an unmigrated item.                                            | yes               |
| `asset-locator-unresolved`            | `legacy S3 assets -> managed_asset`                          | An attachment could not be copied into managed storage; its original locator was retained. | no                |
| `asset-deletion-failed`               | `legacy S3 assets -> managed_asset`                          | A copied attachment could not be deleted from the old bucket.                              | no                |

Any warning whose code is not in `allowedWarningCodes`, and any other unexpected state, aborts startup. On restart, existing report rows remain and orchestration logs only newly appended rows.

A `RAISE EXCEPTION` rolls back its own `DO $$` block, so an abort can leave nothing behind in `migration_report`; the exception message is the only thing an operator sees. Abort messages therefore state what was found — with a bounded sample of offending identifiers — why it blocks the migration, and whether the fix is to change the V1 data, use a different build, or report a migration defect.

## Validation Runbook

Restore a legacy dump, run migration-only mode, then inspect logs, `migration_report`, and migrated rows in the same database:

```bash
just restore-db 'tmp/file.sql'
cd 'apps/server' && bun run run-migration
```

The god-mode Migration Report shows warnings first, then newest rows. Validate both normal and larger available dumps; generated-SQL tests do not exercise startup orchestration, external assets, or realistic volume.
