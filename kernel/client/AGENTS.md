# Kernel Client Guidelines

- Define application I/O and workflows as Effect service classes. Compose dependencies with layers and run them through the shared client `ManagedRuntime`.
- Keep routes as React adapters: resolve services, manage navigation and display state, and inject focused operations into presentational components.
- Decide route access in `beforeLoad` and load route data in `loader`. A redirect or a fetch that the route's identity depends on must never run from a component effect. Return resolved values from `beforeLoad` so components read them from route context instead of recomputing them, and present waiting, failure, and unresolved states with `pendingComponent`, `errorComponent`, and `notFound` rather than hand-rolled status state.
- Keep browser storage, transport, and third-party clients inside their live service layers.
- Keep every layer in `ClientLive` synchronously constructible. `main.tsx` resolves the runtime with `runSync`, which builds the whole graph, so an `Effect.promise` or `Effect.tryPromise` in a layer effect fails at boot on every platform. Defer asynchronous setup into the service's own operations.
- Expose semantic application data and capabilities through the environment-neutral `@ryot/client-sdk` surface so kernel and plugin call sites use the same API. Back kernel calls with direct adapters and plugin calls with the per-session `MessageChannel` adapter; transport differences must not leak into application code.
- Keep kernel-owned concerns such as authentication, server selection, browser history ownership, artifact lifecycle, and bridge dispatch in kernel services. Do not expose them to plugins only to make the implementations look identical.
- Test services with deterministic `Layer.succeed` implementations and plain recording functions. Do not use module mocks, spies, or mock functions.
- Native app name, identifier, and icon belong to each platform's build configuration, never to a literal in `Info.plist`, `strings.xml`, or `capacitor.config.ts`. Keep `capacitor.config.ts` on the production identity and free of environment branching.
- Native and web icons are generated from `assets/` by `bun run generate-assets`. Change the source images or `scripts/generate-assets.ts`; never hand-edit emitted `mipmap-*`, `drawable-*`, or `Assets.xcassets` files, and keep every generation pass and the fixup it needs in that script so a regeneration cannot silently revert one.
- Route an incoming native URL through `resolveDeepLinkHref` and the router. Native navigation must not read `window.location` or push history of its own.
- `/oauth/login` is a server-side contract, not an ordinary app route. The server serves it from its SPA build while native can run a different bundled version; keep its URL, signed `oauth_query` handling, and independence from `ServerService` stable across releases.
- The left-edge gesture and the mobile header's leading control must both derive from `resolveEdge`, so a swipe can never contradict the control the user sees. Adding a route that owns its own back affordance means teaching that resolver, not special-casing either consumer.
- `resolveEdge` returns an `owner` alongside the `intent`, and exactly one document mounts an edge strip. The kernel keeps the edge for the drawer and for back on kernel-rendered routes; a plugin child route hands the edge to the plugin document, which owns both screens and can therefore animate. The plugin executes that gesture but never decides it: it receives the verdict as `edgeBack` on the location message and commits by posting `navigate-back`, leaving the pop to the kernel. Never stream per-frame gesture data across the bridge.
- `resolveEdge` also owns the viewport class, and `compact` travels on the location message beside `edgeBack`. The plugin document must never measure the viewport itself: media queries inside the iframe see the content area, not the window. One definition of compact, in the resolver.
- The location message carries the history `index` and `key`. They are the plugin screen stack's only means of telling push from pop from replace, so a navigation path that cannot supply them must not exist. Read them through `historyEntry`, which is the one place allowed to touch TanStack's `__TSR_*` state fields.
- The mobile drawer is a controlled overlay, not a `<dialog>`. `showModal()` cannot be dragged progressively open, so the panel and scrim must stay driven by the shared progress motion value that the edge gesture writes. A route that has no drawer must not unmount it directly either; the drawer leaves the tree once that progress value reaches zero.
- Android hardware Back runs registered `BackInterceptors` before it pops history. An overlay that can be dismissed registers one while open rather than attaching its own Capacitor listener.
