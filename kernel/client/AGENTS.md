# Kernel Client Guidelines

Architecture and rationale live in `README.md`.

- Define application I/O and workflows as Effect service classes. Compose dependencies with layers and run them through the shared client `ManagedRuntime`.
- Keep routes as React adapters: resolve services, manage navigation and display state, and inject focused operations into presentational components.
- Decide route access in `beforeLoad` and load route data in `loader`; never redirect or fetch route-defining data from a component effect. Return resolved values from `beforeLoad` so components read them from route context, and present waiting, failure, and unresolved states with `pendingComponent`, `errorComponent`, and `notFound`.
- Keep browser storage, transport, and third-party clients inside their live service layers.
- Keep the generated contract client inside `#/api`. Only `AuthenticatedApi` and `AdminApi` run a contract program, and `ClientLive` does not export them. Every other module depends on a narrow group port such as `RyotQLApi` or `SavedViewsApi`; adding an endpoint widens its port rather than handing a service the whole client.
- Keep every layer in `ClientLive` synchronously constructible. Defer asynchronous setup into the service's own operations.
- Expose semantic application data and capabilities through the environment-neutral `@ryot-app/client-sdk` surface so kernel and plugin call sites use the same API. Transport differences must not leak into application code.
- Keep kernel-owned concerns — authentication, server selection, browser history ownership, artifact lifecycle, bridge dispatch — in kernel services. Do not expose them to plugins only to make the implementations look identical.
- Test services with deterministic `Layer.succeed` implementations and plain recording functions. Do not use module mocks, spies, or mock functions. Build API port test layers with the shared makers in `#/api/ports.test-layer`; a test file must not assemble a port layer of its own.
- Keep native app name, identifier, and icon in each platform's build configuration, never in a literal in `Info.plist`, `strings.xml`, or `capacitor.config.ts`. Keep `capacitor.config.ts` on the production identity and free of environment branching.
- Generate native and web icons from `assets/` with `bun run generate-assets`. Change the source images or `scripts/generate-assets.ts`, and keep every generation pass and its fixup in that script; never hand-edit emitted `mipmap-*`, `drawable-*`, or `Assets.xcassets` files.
- Route an incoming native URL through `resolveDeepLinkHref` and the router. Native navigation must not read `window.location` or push history of its own.
- Treat `/oauth/login` as a server-side contract, not an ordinary app route. Keep its URL, signed `oauth_query` handling, and independence from `ServerService` stable across releases.
- Derive both the left-edge gesture and the mobile header's leading control from `resolveEdge`. A route that owns its own back affordance teaches the resolver rather than special-casing either consumer.
- Render every kernel route through `AppScreen`, which owns the route's `<main>`, its scroll container, its `<h1>`, and its document title. A route passes it content and semantics, never layout classes: the frame owns the gutters and the header-to-content rhythm, and a narrower column is `width="readable"`. The `<main>` keeps only scrolling, the background, and the bottom inset. Never mount a second mobile bar: `ScreenFrame` from `@ryot-app/client-ui-sdk` is the only implementation, and a branch that cannot use `AppScreen` because it must keep a sibling mounted composes `ScreenFrame` with `useScreenLeadingControl` instead.
- Take the safe-area inset from `useSafeAreaTop` in the shell and pass it down; never read `env(safe-area-inset-top)` in JavaScript at a call site, and never assume it is non-zero inside the plugin iframe.
- Keep `PluginHost` driven by props. It receives `compact` on `navigation`, plus `safeAreaTop`, `chromeLeading`, and `chromeTriggerRef`, so it never reaches into shell context and stays renderable in isolation.
- Mount exactly one edge strip per document, chosen by the `owner` that `resolveEdge` returns. A plugin executes the gesture but never decides it: it receives the verdict as `edgeBack` on the location message and commits by posting `navigate-back`, leaving the pop to the kernel. Never stream per-frame gesture data across the bridge.
- Take the viewport class from `resolveEdge`, which sends `compact` on the location message beside `edgeBack`. The plugin document must never measure the viewport itself.
- Read the history `index` and `key` through `historyEntry`, the one place allowed to touch TanStack's `__TSR_*` state fields. A navigation path that cannot supply them must not exist.
- Declare every route's document title through `usePageTitle`, with exactly one caller mounted per tree. `AppScreen`, `AuthStatus`, and `SavedViewNotice` call it for every route they render, so their consumers must not call it again. `PluginHost` owns no title; the plugin route is the single title owner for every branch it renders.
- Keep the skip link and the route announcer in `__root.tsx`. Every route renders exactly one `<main>` carrying `mainContentProps`, including each pending, error, not-found, and plugin-ready branch.
- Make the rest of the page inert behind an overlay, not merely focus-trapped. Portalled overlays get this from the SDK's `useInertBackground`; the mobile drawer sets `inert` on its own content wrapper.
- Take modal, menu, focus-trap, scroll-lock, outside-dismiss, and Escape behaviour from `@ryot-app/client-ui-sdk`; never hand-roll another overlay here. An overlay the kernel owns rather than renders through `Modal` or `Menu` still wraps its content in `OverlayScope`, and a route never disables its own shortcuts because an overlay is open. Back interception stays kernel-owned and travels into the SDK as an injected `onInterceptBack`; the SDK must never import `BackInterceptors`, the router, or Capacitor.
- Render every icon with `AppIcon` from `@ryot-app/client-ui-sdk/icon`, addressed by registered name. Never import `lucide-react` here or inline an `<svg>`; a missing glyph is a name to register in the SDK, not an icon to hand-roll at the call site.
- Release the drawer's scroll lock through the `unlock` that `useScrollLock` returns, not effect cleanup. `closeThen` restores overflow and then navigates inside one `flushSync`.
- Keep a selected upload file-backed as a `Blob`/`File` through picker, form field, and transport, reaching the server through the `@ryot-app/client-sdk` uploads capability. Never read a selected file into memory, and never re-implement intent creation, byte transfer, or completion at a call site.
- Drive the mobile drawer's panel and scrim from the shared progress motion value the edge gesture writes; it is a controlled overlay, not a `<dialog>`. A route that has no drawer must not unmount it directly — the drawer leaves the tree once that progress value reaches zero.
- Position a route-owned overlay against a `relative` wrapper the route itself renders around its scroll container, because the shell's content wrapper carries the drawer's motion transform.
- Register a `BackInterceptor` for a state-owned overlay rather than attaching its own Capacitor listener; Android hardware Back runs interceptors before it pops history. An overlay whose open state lives in the URL is a history entry instead: it opens with a push, registers nothing, and closes by popping the entry it pushed, falling back to a replace when it was entered directly.
- Keep the pieces the settings features share in `modules/ui/` — catalog picking, the wizard shell and its step label, run status and progress, schema-form review rows, icons and temporary uploads, the destructive confirmation, the retryable load error, and `StatusState`. `modules/ui` must stay free of feature vocabulary: a feature supplies its own `toEntry`, choose label, step list, and step headings. Import-run vocabulary belongs to `modules/imports` and integrations reads it from there; never keep a second copy of a run's counts, failure reasons, or outcome label.
- Open a URL-owned settings overlay through `useSearchParamModal`. It pushes the entry, pops the entry it pushed, replaces when the overlay was entered directly, and defers the caller's reload until the overlay has actually left; never hand-roll that ref pair in a route again.
- Reach the server through a contract group port. The backup archive is the single exception, because it is a byte stream the browser has to be handed as a file: `BackupsApi.downloadArchive` takes the bearer header from `AuthenticatedApi.authorization` and fetches the endpoint itself. Nothing else may ask for that header.
- Let `SettingsFrame` own a settings route's `<h1>` through `title` and `meta`. A detail view renders no heading of its own at any breakpoint.
- Give a compact route only the controls that fit a 54px bar, each drawn with `ScreenBarButton`. Search takes the bar over through `searchRow`, which supplies that row's children rather than a row of its own, mounts its field focused, and registers a `BackInterceptor` while it is open. Every exit path flushes the close and then focuses the bar control that opened it, which is unmounted while the row is up. Layout and filters move into a bottom sheet built from `Modal` with `containerClassName="items-end"`.
- Poll a non-terminal run through `useRunPolling`, which ticks only while the document is visible and stops once the run settles. Never hand-roll an interval in a route.
- Source the desktop sidebar and mobile drawer from the same `SidebarNav`, fed by the `_authenticated` loader, never a component fetch.
- Let the shell own the single sidebar-customization draft and publish it through context; pick the frame with `useIsDesktop`, never a CSS `md:` toggle. Save as a plan of saved-view updates and reorders, then leave, and only then `router.invalidate()`, subscribed to the router's next `onResolved` rather than called around the leave. Never patch loaded navigation data in place.
